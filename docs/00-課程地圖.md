# 課程地圖

這份教材分成兩節實作課，三支範例程式，每一支只練一件事：

```text
lab1_flight.py    操控無人機          （不碰影像）
lab2_capture.py   影像進電腦、拍照存檔 （不碰飛行）
lab3_detect.py    兩者整合 + YOLO 辨識
```

**一次只練一件事，出問題才找得到原因。** 畫面卡住的時候，如果同時在飛，你分不清
是串流的問題還是飛機在飄。所以前兩支刻意互相隔離，第三支才接起來。

---

## 兩節課總覽

| 節次 | 主題 | 用哪支 | 你會完成什麼 |
|---|---|---|---|
| 第一節 | 操控 + 影像，分開練 | `lab1_flight.py`、`lab2_capture.py` | 讓無人機起飛前進 100 公分再降落；看到即時畫面並按 `P` 拍照 |
| 第二節 | 整合 + 辨識 | `lab3_detect.py` | 邊操控邊看畫面，按 `P` 拍照並對那一張做 YOLO 辨識 |

### 辨識只在按 `P` 的時候做

這是第二節最重要的設計，先講清楚：**我們不做連續辨識。**

畫面以來源原本的速度跑，模型完全不介入；只有你按下 `P`，程式才對那一張跑一次
YOLO。理由是實測的數字：CPU 上 `yolo26n` 一張要 50~60 ms，連續跑會把畫面壓到個位數
fps —— 那個更新率沒辦法操控無人機。

細節見 [03-lab3.md](03-lab3.md)。

## 課前一定要做

### 1. 確認 Python 版本

```bat
python --version
```

要 **3.10 ~ 3.13**，建議 **3.12**（教材實測的版本）。上限是 `torch==2.7.0` 的 wheel
決定的，3.14 以上裝不起來。詳見 [../README.md](../README.md) 步驟 0。

### 2. 安裝套件

```bat
python -m venv .venv
.venv\Scripts\activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```

約 1.9 GB（PyTorch 占 1.2 GB），實測純解壓就要 2 分 27 秒。**請不要留到上課才裝。**

> `lab1_flight.py` 其實只需要 `djitellopy`，連 opencv 都不用。所以就算 PyTorch
> 裝失敗，第一節的操控部分照樣能上。

### 3. 放好 YOLO 權重

```bat
python -c "from ultralytics import YOLO; YOLO('yolo26n.pt')"
move yolo26n.pt models\
```

只有 `lab3_detect.py` 會用到它。

### 4. 記住 Tello Wi-Fi 的限制

Tello 會自己開一個 `TELLO-XXXXXX` 熱點（沒有密碼）。電腦連上它之後會顯示
「無網際網路」，那是正常的。

**但這代表：連上 Tello 後就不能下載套件或權重。** 所以順序只能是「先在一般網路把
環境裝好 → 再切到 Tello 熱點」。

另外：**一台 Tello 同時只能被一台電腦連。** 同組要輪流。

## 第一節：操控與影像，分開練

### A. 操控（`lab1_flight.py`）

```bat
python labs\lab1_flight.py                      :: 只連線看狀態，不起飛
python labs\lab1_flight.py --path               :: 起飛 -> 前進 100 cm -> 降落
python labs\lab1_flight.py --manual --speed 20  :: 鍵盤操控
```

講義：[01-lab1.md](01-lab1.md)

**這一節的核心問題：路徑控制和手動操控差在哪？**

- `move_forward(100)` 會**等飛機飛完**才返回 —— 不用自己算時間，但飛行途中程式
  什麼都不能做
- `send_rc_control(...)` 送出就返回 —— 必須每 50 ms 重複送，不送它就照最後一筆
  速度繼續飄（這就是「放開不會停」的原因）

### B. 影像（`lab2_capture.py`）

```bat
python labs\lab2_capture.py                     :: 看畫面、按 P 拍照
```

講義：[02-lab2.md](02-lab2.md)

**無人機放桌上開機就好，這一支不會飛。** 按 `T` 也不會起飛 —— 程式會印一行提示叫你
去用 lab1。

**這一節的核心問題：**

- djitellopy 給的是 RGB，cv2 吃 BGR —— 不轉會怎樣？
- `frame_read.frame` 為什麼是「最新一格的快照」而不是佇列？
- `runs\<時間戳>\` 和 `index.jsonl` 裡存了什麼？

## 第二節：整合與辨識

```bat
python labs\lab3_detect.py                      :: 操控 + 畫面 + 按 P 辨識
```

講義：[03-lab3.md](03-lab3.md)

把第一節的兩件事接起來，再加上 YOLO。按 `P` 一次做完三件事：拍照 → 辨識 → 存檔。

**這一節的核心問題：**

- 為什麼模型要在主迴圈**開始前**就載好（實測載入要 3 秒）？
- 為什麼辨識不做連續？
- 為什麼「起飛前必須先看到畫面」這條規則要寫在程式裡，而不只是寫在文件裡？
- COCO 80 類認得什麼、不認得什麼？把 `--conf` 調低會發生什麼事？

## 硬體

| | 數量 | 說明 |
|---|---|---|
| 筆電（Windows 10/11） | 每人一台 | **要能自己切 Wi-Fi**。`lab1 --manual` 用 `msvcrt`，是 Windows 專用 |
| Tello EDU | 每 3~4 人一台 | **一台只能被一台筆電連**，同組要輪流 |
| Tello 電池 | 每台 2~3 顆 | 低於 30% 程式就不讓它起飛 |
| 空曠場地 | — | lab1 的 `--path` 需要前方至少 2 公尺 |

用到的 UDP 埠（排錯時要知道）：**8889** 指令、**8890** 狀態封包、**11111** 影像串流。
上一個 python 沒關乾淨，這些埠會被占住，下一次一定連不上。

## 課前準備（給老師）

1. **前一週就要學生裝好環境並回報。** 驗收方式給一句話：

   ```bat
   python labs\lab3_detect.py --source video --path data\samples\test.mp4 --headless --max-frames 20 --snap-every 10
   ```

   跑得出「拍照辨識 2 次」就算過關。

2. **權重用隨身碟發。** 連上無人機熱點就沒網路了，當場要抓來不及。

3. **電池全部充飽，並把每台的熱點名稱寫在白板上**，不然三十台筆電會連錯機。

4. **先自己跑一次「連不上」的情況**：把無人機關掉再跑，看它重試 **28 秒**才放棄。
   上課前就要跟學生講那段等待是正常的，否則他們會以為當掉、開始亂按、然後占住 UDP 埠。

5. **講清楚 COCO 權重認不得鉛筆。** 學生第一次按 `P` 看到 `0 處` 會問「是不是壞了」。
   那不是壞了，是權重的邊界 —— 見 [90-設計決策.md](90-設計決策.md)。
