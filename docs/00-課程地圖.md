# 課程地圖

## 這門課要做出什麼

一支可以用的 CLI 巡檢工具：把 Tello EDU 的影像接到桌電，跑 YOLO 偵測，把命中的
畫面存進本機並寫成可查的索引。

但工具只是副產品。真正要學的是**一個專案怎麼從能跑變成可用**：哪些決定是刻意的、
為什麼不用看起來更聰明的做法、遇到問題先量還是先改。這部分集中在
[90-設計決策.md](90-設計決策.md)。

---

## 三節課的安排

**總共只有約 100 分鐘的實作時間**（兩節課，每節約 50 分鐘）。這份教材的內容是照這個
長度裁的 —— 裝環境、量測、飛行操控都移到課前或作業，課堂只留「非得當場做」的部分。

| 節 | 時間 | 主題 | 用哪支程式 | 需要無人機 |
|---|---|---|---|---|
| **1** | 50 分 | 無人機影像接到桌電 | `labs\lab3_tello.py --preview-only` | ✓ |
| **2** | 50 分 | 影像辨識：認出瓶子、杯子、書等 | `labs\lab1_detect.py` → `labs\lab2_loop.py` | 選用 |
| **3** | — | 全國實務專題競賽第一名作品介紹 | （由授課老師簡報，本教材不涵蓋） | — |

**選讀**（課堂不帶，當作業或自己玩）：`lab3_tello.py` 的飛行操控、
`lab4_patrol.py` 的三來源整合、`--reload-each` 的載入成本量測、
三組 `--every` 的 fps 對照。

> ⚠️ **環境必須在課前裝好，這不是建議而是前提。** 完整環境即使 wheel 已經在本機、
> 完全不用下載，純解壓也要 **2 分 27 秒**（實測）；要下載的話一台筆電好幾分鐘，
> 三十台共享教室 Wi-Fi 會把整節課吃掉。詳見下一節。

### 為什麼第一節課用的是檔名叫 `lab3` 的那支？

檔名的編號是**程式碼的累積順序**，不是上課順序：

```
lab1_detect  靜態推論                 ← 最單純
lab2_loop    ＝ lab1 ＋ 連續影像迴圈
lab3_tello   ＝ lab2 ＋ 真的無人機      ← 第一節課只讀它的「段落 3」
lab4_patrol  ＝ lab3 ＋ 三來源整合      ← 最完整
```

四支檔案的段落順序完全一樣，所以後面的檔案可以直接 diff 出「多了什麼」。這個累積
關係要靠編號才看得出來，所以檔名不跟著上課順序改。

**第一節課的讀法：** `lab3_tello.py` 有 422 行，但 `--preview-only` 只會走到
段落 1、3、7。段落 2（載入模型）、4（推論）、5（畫框）在預覽模式下**完全不會被
呼叫**，所以第一節課可以整段跳過，第二節再回頭補。

每章講義開頭都標了「這節課要讀哪幾段」。

## 環境建置：全部課前做完

### 實測時間（本機、網路順暢的情況）

| 動作 | 實測 | 備註 |
|---|---|---|
| `python -m venv .venv` | **10 秒** | |
| 裝 `requirements-step1.txt`（265 MB） | **22 秒** | 含實際下載 |
| 裝 `requirements.txt`（1.9 GB） | **2 分 27 秒** | **wheel 已在快取、零下載**的純解壓時間 |
| 下載 `yolo11n.pt`（5.4 MB） | **1.2 秒** | |
| lab1 第一次跑完 8 張 | **14 秒** | 含 import torch + 載模型 + warmup |

**2 分 27 秒那一格是重點**：那是「連下載都不用」的下限。真的要從網路抓 1.9 GB，
一台筆電好幾分鐘；三十台共享教室 Wi-Fi 要乘好幾倍。**100 分鐘的課撐不起這個。**

### 結論：兩段都在課前裝完

| 環境 | 大小 | 什麼時候 |
|---|---|---|
| `requirements-step1.txt` | 265 MB | 課前（第一節課只需要這個） |
| `requirements.txt`（含 PyTorch） | 1.9 GB | 課前（第二節課開始需要） |
| `yolo11n.pt` | 5.4 MB | 課前，老師用隨身碟發最保險 |

為什麼還要保留兩段式的拆法？因為**第一節課真的只需要 265 MB**
（`--preview-only` 不碰模型，實測過）。萬一有學生 PyTorch 裝失敗，他第一節課照樣
能完整參與 —— 這是一條備援路線，不是省時間的手段。

> 這個拆法是程式結構本來就支援的：`from ultralytics import YOLO` 寫在
> `load_model()` **函式裡**，所以預覽模式完全不會載入 PyTorch。
> **import 寫在哪裡，會決定使用者要裝多少東西。**

### ⚠️ 連上 TELLO 熱點就沒有網路了

這件事會毀掉第一節課，一定要先講：

```
Tello 是自己開一個 Wi-Fi 熱點（TELLO-XXXXXX），沒有對外網路。
筆電連上它 = 斷網 = 不能 pip install、不能下載權重。
```

所以順序只能是：**先用校園網路把所有東西裝好 → 再切到 TELLO 熱點**。課堂上發現
少裝東西的人，得先切回校園網路、裝完、再切回來 —— 那一趟就是 5 分鐘以上。

**這就是為什麼環境一定要課前完成。**

## 第一節課：無人機影像到桌電（50 分鐘）

詳細講義見 [03-lab3.md](03-lab3.md)。**這節課不飛。**

| 分鐘 | 做什麼 | 要用網路嗎 |
|---|---|---|
| 0–5 | **環境自檢**：`python labs\lab4_patrol.py --source image --path data\samples --dry-run --headless`　跑得過就代表環境 OK（不需網路、不需無人機、不需模型） | ✗ |
| 5–12 | 講硬體與 Wi-Fi：Tello 是熱點、**連上去就斷網**、UDP 8889／11111 是什麼 | ✗ |
| 12–25 | 切到 `TELLO-XXXXXX` 熱點 → `python labs\lab3_tello.py --preview-only` → **看到畫面** | ✗ |
| 25–33 | 按 `P` 拍一張 → `Q` 離開 → 看 `runs\<時間戳>\` 的 jpg 與 `index.jsonl` | ✗ |
| 33–45 | 讀程式：只讀**段落 3 影像來源**（`connect` → `streamon` → `frame` → RGB 轉 BGR） | ✗ |
| 45–50 | 排錯緩衝 + 交代第二節課前要做的事 | |

**12–25 那一格是這節課的核心，也是最會爆的一格。** 排了 13 分鐘，因為一定有人連不上。
常見狀況（完整對照表在 [91-排錯手冊.md](91-排錯手冊.md)）：

- Wi-Fi 沒連到熱點 → 程式會重試 **28 秒**才放棄。**那不是卡住，要先講，否則學生會亂按**
- 上一個 python 還開著 → 占住 UDP 8889 / 11111，下一次一定連不上
- 電量低於 50% → 無人機拒絕指令

> 起飛、降落、鍵盤操控都是選讀，這節課不碰。`--preview-only` 不需要飛也看得到畫面，
> 無人機放在桌上開機就行。真要飛請先讀 [03-lab3.md](03-lab3.md) 的首飛檢查表。

## 第二節課：影像辨識（50 分鐘）

詳細講義見 [01-lab1.md](01-lab1.md) 與 [02-lab2.md](02-lab2.md)。

| 分鐘 | 做什麼 |
|---|---|
| 0–8 | 跑內附素材：`python labs\lab1_detect.py --source data\samples --headless`（實測 14 秒）→ 看 `index.jsonl`，解釋「模型載入只付一次」 |
| 8–22 | **瓶子 vs 鉛筆**：桌上擺瓶子＋鉛筆，手機拍一張存到 `data\mine\`，跑 `lab1_detect.py --source data\mine`（不加 `--headless`，要看畫面） |
| 22–30 | 瓶子有框、鉛筆沒反應。加 `--conf 0.05` 再跑一次，證明**門檻調不出一個不存在的類別** |
| 30–42 | **即時辨識**：`lab2_loop.py --source 0`（筆電鏡頭）或接回無人機 `lab3_tello.py --every 10` |
| 42–48 | 講 `--every`／`--threshold`／`--cooldown` 三個參數在調什麼（用講義裡現成的數字，**不現場跑三次對照**） |
| 48–50 | 交代作業 |

**8–30 那 22 分鐘是這節課的重點。** 不是教 YOLO 怎麼用，是讓學生親眼看到預訓練權重
的邊界 —— 瓶子中、鉛筆不中，而且調門檻救不回來。

課堂上**不做**的（都移到作業，見 [92-作業與評分.md](92-作業與評分.md)）：

- `--reload-each` 量「每張重建模型」的成本（要跑兩次 + 解說，約 10 分鐘）
- 三組 `--every` 的 fps 對照表（要跑三次）

### 課堂素材：哪些東西認得出來

`yolo11n.pt` 是 COCO 預訓練權重，只認得 **80 類**。擺桌上這些會中：

| 認得 | COCO 類別名 |
|---|---|
| 瓶子 | `bottle` |
| 杯子 | `cup` |
| 書 | `book` |
| 剪刀 | `scissors` |
| 手機 | `cell phone` |
| 筆電 / 滑鼠 / 鍵盤 | `laptop` / `mouse` / `keyboard` |
| 人 | `person` |

**鉛筆、原子筆不在 80 類裡**（沒有 `pencil`、也沒有 `pen`）。

這不是缺陷，是課堂上最好的教材：**同一張照片裡放瓶子和鉛筆**，瓶子框起來、鉛筆沒
反應 —— 預訓練權重的邊界當場看得見。想要它認鉛筆，就得自己收資料訓練，那是另一門課。

> 內附的 `data\samples\` 是合成的幾何圖形，COCO 裡當然沒有這些類別。實測跑下去
> 模型會把圓形標成 **`sports ball`（球）**、三角形標成 **`kite`（風箏）**、
> 方塊標成 **`tv`**，最高分 0.32。**分類模型永遠會給你一個答案，而且會附一個
> 看起來很有把握的分數。** 詳見 [90-設計決策.md](90-設計決策.md) 的「誠實的限制」。

## 硬體

| | 數量 | 說明 |
|---|---|---|
| 筆電（Windows 10/11） | 每人一台 | **要能自己切換 Wi-Fi**（學校鎖網路的話第一節課做不了）。第二節若要用鏡頭辨識，最好有內建相機 |
| Tello EDU | 每 3~4 人一台 | 第一節必備。**一台 Tello 同時只能被一台筆電連**，所以同組要輪流 |
| Tello 電池 | 每台 2~3 顆 | 低於 50% 會拒絕指令。一顆飛行約 10~13 分鐘，純串流比較省 |
| 桌上小物 | 每組一套 | 瓶子、杯子、書、剪刀、手機 + **一支鉛筆（反例，很重要）** |
| 空曠場地 | — | 只有選讀的飛行操控需要 |

### Wi-Fi 的三件事（第一節課會卡在這裡）

1. **Tello 是 AP 模式**：它自己開一個 `TELLO-XXXXXX` 熱點，**沒有密碼**。
   筆電要主動連上去。
2. **連上去就沒有對外網路。** Windows 會顯示「無網際網路」，那是正常的。
   所以不能邊連無人機邊 pip install。
3. **一對一**：一台 Tello 只能接一台筆電。同組三個人要輪流連，
   或者分工（一個人連、其他人看螢幕讀程式）。

> Tello EDU 有「多機 station 模式」可以讓多台連同一個路由器，但那需要額外設定，
> 100 分鐘的課不碰。

用到的通訊埠（排錯時要知道）：

| 埠 | 做什麼 |
|---|---|
| UDP 8889 | 送指令、收回應（`connect` / `streamon` 走這裡） |
| UDP 8890 | 無人機每 0.1 秒推一次狀態（電量、高度就是從這來的） |
| UDP 11111 | 影像串流（H.264） |

**上一個 python 沒關乾淨，這些埠會被占住，下一次一定連不上。** 這是第一節課
最常見的故障。

第二節課沒有無人機也能上（用筆電鏡頭或內附的 `data\samples\`）。

## 課前準備（給老師）

100 分鐘的課，這幾件事沒做完就一定上不完。

1. **前一週就要學生裝好完整環境並回報。** 不是「建議」——
   實測純解壓就要 2 分 27 秒，要下載更久。驗收方式給學生一句話：

   ```bat
   python labs\lab1_detect.py --source data\samples --headless
   ```

   跑得出「處理 8 張」就算過關，請他們把那行貼給你。

2. **權重用隨身碟發，不要讓學生自己下載。** `yolo11n.pt` 只有 5.4 MB，但第一節課
   連上無人機熱點就沒網路了，當場要抓就來不及。直接放進 `models\`。

3. **確認學生筆電能自己切 Wi-Fi。** 學校如果鎖了網路設定，第一節課直接做不了 ——
   這要在課前確認，不是上課才發現。

4. **Tello 電池全部充飽，每台備 2~3 顆。** 低於 50% 會拒絕指令。
   另外確認每台的熱點名稱（`TELLO-XXXXXX`），分組時直接寫在白板上，
   不然三十台筆電會連錯機。

5. **先自己跑一次「連不上」的情況。** 把無人機關掉、跑 `--preview-only`，
   看它重試 28 秒然後印出兩條檢查。**上課前十分鐘就要跟學生講這段等待是正常的**，
   否則他們會以為當掉、開始亂按、然後占住 UDP 埠。

6. **講清楚鉛筆偵測不到、圓形會被判成球。** 學生第一次跑會問「是不是壞了」。
   那不是壞了，是權重的邊界 —— 而且那正是第二節課最值得講的二十分鐘。
