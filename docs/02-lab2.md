# Lab 2：YOLO 辨識範例

> 檔案：`labs\lab2_detect.py`　**第一節課後半**　不需要無人機
> 　需要先裝好 [../README.md](../README.md) 的 `requirements.txt`

這節課接在 [01-lab1.md](01-lab1.md) 後面。前半你已經確認 Tello 可以拍照，這裡要確認
YOLO 可以在本機跑起來，並看懂「模型認得什麼、不認得什麼」。

本章會讀**全部七個段落**。剛剛在 `lab3` 跳過的段落 2（載入模型）、4（推論）、
5（畫框），在這裡是主角。

## 課堂素材：桌上擺什麼

`yolo26n.pt` 只認得 COCO 的 **80 類**。擺這些會中：

| 認得 | COCO 類別名 |
|---|---|
| 瓶子 | `bottle` |
| 杯子 | `cup` |
| 書 | `book` |
| 剪刀 | `scissors` |
| 手機 | `cell phone` |
| 筆電 / 滑鼠 / 鍵盤 | `laptop` / `mouse` / `keyboard` |
| 人 | `person` |

**鉛筆和原子筆不在 80 類裡**（沒有 `pencil`，也沒有 `pen`）。

所以請**在同一張照片裡放一個瓶子和一支鉛筆**，拍下來跑一次 —— 瓶子會被框起來、
鉛筆完全沒反應。那一張照片就是這節課最重要的教材：**預訓練權重的邊界看得見了。**

## 1. 這節課要做什麼

把一批照片跑過 YOLO，畫上框，存成檔案，並寫一份可以查的索引。

跑完你會有一個 `runs\<時間戳>\` 資料夾，裡面是標註圖和一份 `index.jsonl` ——
**跟第一節課按 `P` 存出來的格式完全一樣**。那不是巧合：輸出格式一開始就定下來，
後面每一支程式都沿用，所以你第一節課看過的東西，這節課直接看得懂。

## 2. 先跑起來

先跑，再讀程式碼。看得到輸出，讀起來才有意義。

先用內附的素材（照片已經放好，不用自己拍）：

```bat
.venv\Scripts\activate
python labs\lab2_detect.py --source data\samples --headless
```

應該會看到類似：

```
來源 data\samples：8 張
模型載入 + warmup：3015 ms（整批只付一次）
[1/8] sample_01.jpg  0 處  最高 0.00  推論 89 ms
[2/8] sample_02.jpg  0 處  最高 0.00  推論 49 ms
[3/8] sample_03.jpg  0 處  最高 0.00  推論 54 ms
[4/8] sample_04.jpg  0 處  最高 0.00  推論 52 ms
...
處理 8 張、略過 0 張，平均推論 57 ms
輸出：runs\20261002_195928
```

再看索引：

```bat
type runs\20261002_195928\index.jsonl
```

> **全部 `0 處` 不是壞了。** 內附素材是**合成的幾何圖形**（圓形、方塊、三角形），
> 而 `yolo26n.pt` 只認得 COCO 那 80 類 —— 裡面沒有「圓形」也沒有「方塊」。
> 這一節要驗收的是**整條管線**，不是模型準不準。
>
> 想看它「硬要給答案」，把門檻降到 0.05：
>
> ```bat
> python labs\lab2_detect.py --source data\samples --headless --conf 0.05
> ```
>
> 會冒出 9 個框：圓形被說成 `orange`（橘子）6 次、`bicycle` 2 次、`tv` 1 次，
> 但**最高分只有 0.17**。它自己也沒把握，是你把門檻放得太低。
> 詳見 [90-設計決策.md](90-設計決策.md) 的「誠實的限制」。

### 換成你自己拍的照片 —— 瓶子 vs 鉛筆

這是第一節最值得親眼看的測試。桌上擺一個瓶子、一支鉛筆，手機拍一張，存到
`data\mine\`，然後**不要加 `--headless`**（要看畫面）：

```bat
python labs\lab2_detect.py --source data\mine
```

按任意鍵下一張、`q` 離開。你會看到：

- **瓶子被框起來**，標籤是 `bottle` 加上一個百分比
- **鉛筆什麼都沒有** —— 不是沒框準，是模型裡根本沒有這個類別

把門檻降到最低再試一次，確認不是門檻的問題：

```bat
python labs\lab2_detect.py --source data\mine --conf 0.05
```

鉛筆**還是不會被認出來**（頂多被硬塞成某個相近的類別）。
`--conf` 調的是「多有把握才回報」，調不出一個不存在的類別。

> **這就是 COCO 80 類的邊界。** 要它認鉛筆，只有一條路：自己收集鉛筆的照片、
> 標註、訓練一顆新權重。那是另一門課的範圍（見
> [90-設計決策.md](90-設計決策.md) 的「誠實的限制」），但**換上去只要改
> `--weights`，這支程式一行都不用動** —— 那是介面設計對了的證據。

## 3. 程式碼導讀

打開 `labs\lab2_detect.py`。七個段落，從上讀到下。

### 段落 2：載入模型

```python
model = YOLO(weights)
model.predict(np.zeros((640, 640, 3), np.uint8), verbose=False)   # warmup
```

**兩件事都在迴圈外面。** 課堂上看一下輸出的第二行就好：

```
模型載入 + warmup：4794 ms（整批只付一次）
```

4.8 秒，但**整批 8 張只付一次**。後面每張只要 45 ms。

> **課後自己量**（課堂時間不夠，留作業）：`--reload-each` 刻意改成每張圖都重新
> 載入一次模型。
>
> ```bat
> python labs\lab2_detect.py --source data\samples --headless --reload-each
> ```
>
> 這不是假想的錯誤，是很常見的寫法：把 `YOLO(weights)` 寫進處理迴圈裡面。
> 細節見 [90-設計決策.md](90-設計決策.md) 第 1 條。

**warmup 為什麼也要：** 第一次推論要付 lazy 初始化成本。不 warmup 的話第一張特別
慢，你算出來的「平均延遲」就被它拉歪了。量測要先讓系統進入穩定狀態。

### 段落 3：影像來源

```python
if path.is_file():
    return [path]
```

`--source` 給檔案就一張，給資料夾就整批。`sorted()` 是刻意的：資料夾的列出順序
不保證，排序過輸出才可重現。

### 段落 4：推論

```python
result = model.predict(frame, conf=conf, verbose=False)[0]
```

`predict()` 收一批圖回一串結果，我們一次只給一張，所以取 `[0]`。
`verbose=False` 是因為 ultralytics 預設每張都印一行它自己的 log，會把我們的輸出
洗掉。

然後把它的結果轉成我們自己的 `Detection`：

```python
Detection = namedtuple("Detection", "x1 y1 x2 y2 score name")
```

**為什麼不直接傳 ultralytics 的物件到處跑？** 因為那樣整支程式就綁死在
ultralytics 上了。換成別的模型（或 lab3 的 `--dry-run` 根本沒有模型）時，只有段落
4 要改，段落 5、6 一行都不用動。這叫「在邊界上轉換格式」。

### 段落 5：畫框

只用 `cv2`，不拉別的繪圖套件。像 matplotlib 這種通用繪圖庫每張圖要多花
100~300 ms 在建 figure；純 cv2 畫一張 1080p 約 2~5 ms。

注意 `draw()` 第一行是 `out = frame.copy()`：**不修改輸入**。等到 lab2 你會同時
需要原始幀和標註幀，那時就會感謝這個決定。

還有 `_color()`：

```python
return COLORS[sum(name.encode()) % len(COLORS)]
```

不用 `hash()` —— Python 的字串 hash 每次啟動都不同，顏色會在每次執行時亂跳。

### 段落 6：存檔

```python
cv2.imwrite(str(run_dir / name), image)
...
with (run_dir / "index.jsonl").open("a", encoding="utf-8") as f:
```

兩個決定：

- **先落地本機，迴圈裡不碰網路。** 存檔要能在沒網路、沒金鑰的情況下成功。
- **索引用 `.jsonl`（一行一筆）而不是一整包 `.json`。** 程式被 `Ctrl-C`，已經寫
  進去的行仍然是合法內容；整包 json 會因為缺一個 `]` 而整個讀不出來。

### 段落 7：主迴圈

```python
if frame is None:
    print(f"  略過讀不進來的檔案：{path.name}")
    skipped += 1
    continue
```

**一張壞圖不該中斷整批。** 使用者選了 200 張，第 3 張壞了就整個停掉是最糟的體驗。
印一行、跳過、繼續 —— 但要計數，最後摘要裡要說清楚略過了幾張。

這章的語意是**一張不漏**：每一張都推論、每一張都存，不看門檻、沒有冷卻。
lab2 的語意剛好相反，到時候再比較。

## 4. 動手改

1. **把信心度門檻調低**：`--conf 0.05`。多了幾個框？框得對嗎？
   （這是「低門檻換高召回率」的代價，直接看得到。）
2. **在 `index.jsonl` 多存一個欄位**：影像的寬高。
   提示：`frame.shape[:2]` 是 `(高, 寬)`。
3. **讓 `--source` 支援遞迴搜尋子資料夾。** 提示：`Path.rglob("*")`。
   想一下：這樣「一張不漏」的承諾還守得住嗎？如果某個子資料夾裡有 5000 張呢？
4. **故意放一個壞檔進去試試。** 建一個 `data\samples\broken.jpg`，內容隨便打幾個
   字。確認程式印出「略過」而不是整批中斷。

## 5. 常見錯誤

| 訊息 | 原因 |
|---|---|
| `ModuleNotFoundError: No module named 'ultralytics'` | 忘了 `.venv\Scripts\activate` |
| 一直卡在 `Downloading yolo26n.pt` | 權重沒放進 `models\`，它在連網下載。見 README 步驟 2 |
| `找不到來源：...` | 路徑打錯。Windows 上用 `\`，路徑有空白要加引號 |
| 全部都 `0 處` | 正常。內附素材是合成圖形，不在 COCO 80 類裡 |
| 加 `--conf 0.05` 後冒出 `orange` / `bicycle` | 那是誤判。門檻放太低，垃圾就進來了 |
| 印出來的中文變成亂碼 | 主控台編碼問題。`chcp 65001` 之後再跑 |
