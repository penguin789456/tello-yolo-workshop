## 1. 這節課要做什麼

從「一批照片」進到「一條停不下來的影像流」。一條主迴圈、每 N 幀推論一次、超過門檻
才存檔。

這章的語意和 lab1 **剛好相反**：lab1 是「一張不漏」，這章是「**處理不完的舊畫面就
丟掉**」。兩種語意都對，只是用在不同場合 —— 而且**不能混在同一個開關裡**。

三件事值得先看懂：

**1. `--loop` 在這裡是必要的。** `test.mp4` **只有 40 幀**（15 fps、約 2.7 秒），
不循環的話 `--max-frames 60` 還沒到就先「來源結束」了。

**2. 只有 `#5`、`#10`、`#15`… 是「辨識」，其餘是「僅顯示」。** 那就是 `--every 5`。
沒推論的幀 `0 處 / 0 ms` 是正常的 —— 它們沒跑過模型。

**3. 辨識幀上那幾個框是誤判，而且值得看一眼。** 把 `--headless` 拿掉跑一次，
你會看到模型把畫面裡的圓形標成 **`sports ball`（球）**、三角形標成 **`kite`（風箏）**。

```bat
python labs\lab2_loop.py --source data\samples\test.mp4 --every 5 --loop --threshold 0.1 --cooldown 0 --headless --max-frames 20
type runs\<時間戳>\index.jsonl
```

`index.jsonl` 裡的 `classes` 會出現 `sports ball`、`kite`、`tv`。COCO 權重裡沒有
「圓形」「三角形」這些類別，它只能在 80 個既有類別裡挑一個最像的。

**這就是「用錯權重」長什麼樣子**：程式沒壞、分數也不算低（0.3 左右），但答案毫無
意義。`--threshold 0.8` 預設值剛好擋掉了它們，所以「自動命中 0 張」。門檻在這裡救了
你一次，但門檻不能救一顆根本不對的模型。

## 3. 程式碼導讀

和 lab1 比對著看最快：

```bat
fc labs\lab1_detect.py labs\lab2_loop.py
```

段落 1、2、4、5 幾乎一樣。真正改的是 3、6、7。

### 段落 3：影像來源 —— 從 list 變成流

```python
cap = cv2.VideoCapture(target)
cap.set(cv2.CAP_PROP_BUFFERSIZE, 1)
```

`CAP_PROP_BUFFERSIZE = 1` 是說「解碼器只要留最新一格」。即時來源的 buffer 裡放的是
**舊資料**，堆著只會讓你看到的畫面離現實越來越遠。

```python
target = int(source) if str(source).isdigit() else str(source)
```

純數字當鏡頭編號、其他當檔案路徑 —— 這是 OpenCV 的慣例。照慣例做，學生在網路上找到
的範例才接得上來。

`read_frame()` 裡的 `--loop`：影片播完就 seek 回第 0 幀。測試時很實用，因為
`test.mp4` 只有幾秒。

### 段落 6：存檔 —— 多了門檻和冷卻

lab1 是每張都存，這章不行。即時來源一秒 30 幀，全存的話幾分鐘就塞爆硬碟，而且
99% 是重複的畫面。

所以自動存檔要兩個條件同時成立：

```python
if run_now and best > args.threshold and \
        (time.perf_counter() - last_save) >= args.cooldown:
```

- `--threshold 0.8`：多高的信心度才算「命中」。注意它比 `--conf` 嚴 —— `--conf`
  決定模型回報什麼，`--threshold` 決定我們認不認。**兩個門檻各有各的用途。**
- `--cooldown 3`：兩次自動存檔至少間隔 3 秒。對著同一個目標，沒有冷卻就會存上百張
  幾乎一樣的圖。

拿掉試試，數一下多了幾張檔案：

```bat
python labs\lab2_loop.py --source data\samples\test.mp4 --threshold 0.1 --cooldown 0 --every 1 --loop --headless --max-frames 100
```

### 段落 7：主迴圈 —— 這章的重點

#### `--every N`：把「畫面」和「推論」解耦

```python
run_now = (idx % args.every == 0) and not args.dry_run
if run_now:
    dets, latency = detect(model, frame, args.conf)
    shown = draw(frame, dets)
else:
    dets, latency = [], 0.0
    shown = frame.copy()
```

沒推論的幀就直接顯示。**這一行是整章的核心**：畫面更新率不再被推論速度綁死。

CPU 上 `yolo11n` 約 10~25 fps，換成更大的模型可能只剩 1 fps 以下。如果每一幀都要等
模型跑完才顯示，畫面就會變成一秒一動 —— 那個更新率**沒辦法操控無人機**，等你看到
障礙物時早就撞上了。所以畫面更新和推論頻率一定要能分開調：

| | 效果 |
|---|---|
| `--every 1` | 全力辨識，畫面跟著推論速度走 |
| `--every 10` | 畫面順，每 10 幀才分析一次 |
| `--every 999` | 幾乎就是純預覽 |

自己比較兩次摘要的「整體 fps」：

```bat
python labs\lab2_loop.py --source data\samples\test.mp4 --every 1  --headless --max-frames 30
python labs\lab2_loop.py --source data\samples\test.mp4 --every 10 --headless --max-frames 30
```

#### 為什麼不排隊？

直覺會想「把每一幀都排進佇列，讓推論慢慢消化」。**不要。** 推論比抓幀慢，佇列只會
越積越長，延遲一路累積 —— 跑幾分鐘之後你看到的是十幾秒前的畫面。

**要最新的結果，就必須丟掉來不及處理的幀。** 摘要裡「跳過 48 幀」不是缺陷，那是設計。

#### `p` 拍一張：手動指令不受自動規則管

```python
if key == ord("p"):
    if not run_now and not args.dry_run:
        dets, latency = detect(model, frame, args.conf)
        shown = draw(frame, dets)
```

兩個刻意的設計：

- **不看門檻、不受冷卻限制。** 這是使用者明確下的指令，就算完全沒偵測到東西也要存。
  自動存檔那條路（門檻 + 冷卻）是另一回事。
- **這一幀如果還沒跑過模型，就單獨為它跑一次。** 使用者要的是有標註的結果，不是一張
  原始畫面。

#### `finally`：不管怎麼離開都要收乾淨

```python
finally:
    cap.release()
    if not args.headless:
        cv2.destroyAllWindows()
```

現在只是釋放一個 `VideoCapture`，感覺沒什麼。到 lab3 這裡會變成「**還在飛就要降落**」
—— 現在先養成習慣。

#### `--headless` 與 `--max-frames`

沒有這兩個參數，這支程式就只能人坐在前面用。有了它們，你可以：

```bat
python labs\lab2_loop.py --source data\samples\test.mp4 --loop --headless --max-frames 60
```

跑完自動結束、印出摘要。**能被無人值守地跑完，是「可測試」的最低門檻。**

## 4. 動手改

1. **把 `--every` 從 5 改成 1 和 20**，各跑一次 `--loop --headless --max-frames 60`，
   記下摘要的「整體 fps」與「推論幾幀」。做成一張三列的表。
2. **讓狀態列多顯示「距離上次存檔幾秒」。** 提示：
   `time.perf_counter() - last_save`。這會讓冷卻變成看得見的東西。
3. **加一個 `--min-gap-frames N`**：規定兩次存檔至少間隔 N 幀（而不是 N 秒）。
   想一下：幀數和秒數哪個比較適合當冷卻單位？來源 fps 會變的時候呢？
4. **把 `--source 0` 接上你的筆電鏡頭**，對著自己跑 `--every 3`。
   （COCO 權重認得 `person`，這次你會真的看到框。）

## 5. 常見錯誤

| 現象 | 原因 |
|---|---|
| 影片播得像快轉 | 你用了 `--headless`。開窗版本會照影片 fps 節流（`cv2.waitKey(delay_ms)`） |
| 按 `q` 沒反應 | 焦點不在影像視窗上。先用滑鼠點一下視窗 |
| `無法開啟來源：0` | 沒有攝影機，或被其他程式（視訊會議軟體）占用 |
| 一張都沒存 | 正常：COCO 權重在合成素材上分數只有 0.3 左右，低於 `--threshold 0.8` |
| CPU 燒滿、電風扇狂轉 | `--every 1` 就是這樣。調大 `--every` |
