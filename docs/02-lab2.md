**一次只練一件事，出問題才找得到原因。** 兩件事接起來是 lab3 要做的。

### 段落 3：讀影格的兩個關鍵

```python
frame = frame_read.frame
if frame is None:
    return "wait"
return cv2.cvtColor(frame, cv2.COLOR_RGB2BGR)
```

**1. djitellopy 給的是 RGB，cv2 全家吃 BGR。**

不轉的話畫面顏色會反過來（天空變橘色）。這是最常見的「看起來能跑但結果怪」的 bug ——
到 lab3 加上 YOLO 之後更嚴重：送進模型的張量跟訓練時不一致，分數會怪。

**2. `frame_read.frame` 是「最新一格的快照」，不是佇列。**

讀它永遠拿到最新的那一格，舊的自然被丟掉，所以**延遲不會累積**。
djitellopy 內部那條解碼執行緒幫我們做了這件事 —— 我們不用自己寫執行緒。

> 對照：`cv2.VideoCapture` 沒有這個性質，它會把解碼好的幀排在 buffer 裡。所以
> `--source video` 那條路加了 `cap.set(cv2.CAP_PROP_BUFFERSIZE, 1)`，叫它少存舊幀。

### `"wait"` 這個第三種回傳值

```python
return None        # 來源結束
return "wait"      # Tello 還沒吐出第一格
return frame       # 正常
```

`streamon` 之後正常 2~3 秒才有第一格畫面。這段期間 `frame` 是 `None`，但那
**不是「來源結束」** —— 如果當成結束，程式一開機就會直接離開。

所以分成三種狀態，而且等待有上限：

```python
FIRST_FRAME_TIMEOUT_S = 10.0
```

等不到就印出可行動的訊息然後結束。**無限等待的程式看起來就像壞了。**

### 段落 5：索引為什麼用 `.jsonl`

```python
with (run_dir / "index.jsonl").open("a", encoding="utf-8") as f:
    f.write(json.dumps(record, ensure_ascii=False) + "\n")
```

jsonl 是**一行一筆、用 append 寫入**。程式被 `Ctrl-C` 或斷電，已經寫進去的行仍然
是合法內容；整包 `.json` 則會因為缺一個 `]` 而整個讀不出來。

## 4. 動手改

1. **在 `index.jsonl` 多存影像的寬高。** 提示：`frame.shape[:2]` 是 `(高, 寬)`。
2. **讓狀態列多顯示「距離上次拍照幾秒」。** 提示：記一個 `last_snap` 時間戳。
3. **加一個 `--interval N`**：每 N 秒自動拍一張（縮時攝影）。
   想一下：這樣還需要 `P` 嗎？兩種都留會不會讓使用者困惑？
4. **故意把 `cv2.cvtColor` 那一行註解掉**，看畫面變成什麼樣子。記下來 —— 以後你
   在別的專案看到同樣的顏色，就知道是什麼問題了。

## 5. 常見錯誤

| 現象 | 原因 |
|---|---|
| `連不上 Tello`（等約 28 秒） | Wi-Fi 沒連到熱點，或上一個 python 還開著占住 UDP 8889 |
| `10 秒內沒有畫面` | 上一次沒關乾淨，UDP 11111 還被占。關掉所有 python，等五秒再試 |
| 畫面顏色很怪、天空是橘的 | RGB/BGR 沒轉（程式已處理；你改過才會這樣） |
| 按 `P` / `Q` 沒反應 | 焦點不在影像視窗上。用滑鼠點一下視窗 |
| 按 `T` 印出「這一節不做飛行操控」 | 設計如此。飛行請用 lab1 |
| `--source video` 說找不到檔案 | 路徑有空白要用雙引號包起來 |
