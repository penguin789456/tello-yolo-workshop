## 3. 程式碼導讀

### 兩種語意，一個分岔

lab1 是「一張不漏」，lab2/lab3 是「丟得起就丟」。這兩件事在 lab4 由 `is_live` 決定：

```python
if source.is_live:
    every, cooldown = max(1, args.every), args.cooldown
    print(f"即時來源（{source.kind}）：每 {every} 幀推論一次，...")
else:
    every, cooldown = 1, 0.0
    print(f"有限來源（{source.kind}）：每一張都推論、每一張都存，一張不漏")
```

存檔條件也跟著分岔：

```python
should_save = run_now and (
    not source.is_live or args.save_all
    or (best > args.threshold
        and (time.perf_counter() - last_save) >= cooldown))
```

**為什麼不做成一個 `--drop-stale` 開關？** 因為兩種行為**剛好相反**，做成一個容易
誤按的開關太危險：按錯了，要嘛漏掉使用者挑的照片，要嘛讓即時畫面延遲累積到沒用。
我們讓它綁在 `--source` 上 —— 來源的性質本來就決定了正確的語意，不該讓使用者選錯。

> 這是一個值得記住的模式：**如果某個選項在某個情境下永遠只有一個正確答案，
> 就不要把它做成選項。**

### 三種來源收斂成一個形狀

```python
Source = namedtuple("Source", "kind handle fps is_live extra")
```

`open_source()` / `read_frame()` / `close_source()` 三個函式裡各有一組 `if kind ==`
分支。**刻意不做 class 繼承**：這支程式要能從上讀到下，三個 `if` 比三個子類別加一個
抽象基底類別好讀 —— 尤其是在只有三種來源、而且不會再長的情況下。

> 什麼時候該換成 class？當來源變成八種、或者每種來源都有自己的一堆狀態要管的時候。
> 三個分支還撐得住就別急著抽象。**抽象是有成本的，成本是讀者要多跳一層。**

`handle` 的型別隨 `kind` 變（list-dict / VideoCapture / Tello），`extra` 只有 tello
用得到（放 `frame_read`）。這種「聯合型別」在小程式裡可以接受，但要註解清楚。

### `read_frame()` 的三種回傳值

```python
return None, ""        # 來源結束
return "wait", ""      # Tello 還沒吐出第一格
return frame, label    # 正常
```

用字串 `"wait"` 當第三種狀態有點土，但它讓主迴圈只需要一個 `isinstance(frame, str)`
就能分辨「結束」和「還沒好」。這兩件事必須分開 —— 把「還沒好」當成「結束」的話，
Tello 一開機就會直接離開程式。

### `--dry-run`：讓程式可以被測試

```python
run_now = (idx % every == 0) and not args.dry_run and not args.preview_only
...
run_dir = None if args.dry_run else open_run(args.out)
```

`--dry-run` 不載模型、不建資料夾、不寫任何檔案，但整條流程照走。

用途：

- 還沒裝好 ultralytics、還沒下載權重，就能確認參數、路徑、來源都對
- 驗證「程式不會在不該寫檔的時候寫檔」
- 當成最低限度的回歸測試：

```bat
python labs\lab4_patrol.py --source image --path data\samples --dry-run --headless
```

跑完 `runs\` 不應該多出任何東西。

### 摘要：量測是交付物的一部分

```
讀 50 幀　推論 10 幀　跳過 40 幀　平均推論 37 ms　整體 85.2 fps
```

跑完要能回答「處理了多少、命中多少、多快」。**沒有數字的「感覺變快了」不是工程。**
有了這份摘要，你對程式做的每個改動才站得住腳 —— 改完再跑一次，數字會告訴你有沒有用。

## 4. 動手改

1. **加 `--summary-json <路徑>`**：把摘要同時寫成一個 json 檔。
   想一下：這個檔該放在 `runs\<時間戳>\` 裡面還是外面？為什麼？
2. **加 `--min-score`**：只把 `best_score` 超過某值的紀錄寫進 `index.jsonl`
   （圖照存）。這和 `--threshold` 的差別是什麼？
3. **寫一支 `report.py` 讀 `index.jsonl`**，印出：總共幾筆、最高分那筆的檔名、
   每個類別各幾筆。這是 jsonl 格式的回報 —— 一行一筆的東西超好處理。
4. **把 `--source image` 換成一個 200 張的資料夾**，觀察「一張不漏」的代價。
   如果有 5000 張呢？你會怎麼改（提示：`--max-frames` 已經在那裡了）。

## 5. 常見錯誤

| 訊息 | 原因 |
|---|---|
| `--source image 需要 --path` | lab4 的來源和路徑是兩個參數，這是刻意的 |
| `--source tello` 但沒有無人機 | 會停在連線錯誤。用 `--source video` 驗收這章 |
| `--dry-run` 還是產生了 `runs\` 資料夾 | 不該發生。如果真的發生了，那是 bug，去找 `open_run` 的呼叫點 |
| 摘要的「推論幀數」不等於 `讀÷every` | 正常：整數除法的餘數，還有你按 `p` 觸發的額外推論 |
