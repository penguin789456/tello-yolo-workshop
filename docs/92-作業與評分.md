# 作業與評分

三份作業，對應三節課的安排：

| 作業 | 對應 | 權重 |
|---|---|---|
| 一 | 第一節課（無人機影像到桌電） | 30% |
| 二 | 第二節課（影像辨識） | 40% |
| 三 | 選讀，二選一（飛行紀錄 / 整合工具） | 30% |

> 權重是建議值，授課老師可自行調整。第三節課是競賽作品介紹，不配作業。

**共同要求：每份作業都要有「數字」和「為什麼」。** 「我覺得變快了」不算答案，
「從 8.2 秒降到 1.9 秒，因為模型只載入一次」才算。

## 作業一（第一節課）：把影像接到桌電　30%

### 要交什麼

1. **一張你自己按 `P` 拍下來的畫面**（`runs\<時間戳>\*.jpg`）
2. **對應的那一行 `index.jsonl`**（貼上文字即可）
3. 一份不超過一頁的報告，回答四個問題：

   - **Q1** 你的環境裝了哪些套件？用 `pip list` 的輸出證明 **`torch` 不在裡面**。
   - **Q2** 既然沒有 `torch`，為什麼 `lab3_tello.py --preview-only` 跑得起來？
     （提示：去看 `load_model()` 裡的 `from ultralytics import YOLO` 寫在哪一行，
     以及 `--preview-only` 會不會呼叫到那個函式。）
   - **Q3** 把 `--preview-only` 拿掉再跑一次，會發生什麼事？錯誤訊息是什麼？
     為什麼那個錯誤是**合理**的？
   - **Q4** 你連線時卡在哪一步？花了多久？（沒卡住就寫「沒有」。）
     如果連不上，程式會重試幾秒才放棄？那段等待期間程式是壞了還是正常？

### 評分

| 項目 | 分數 |
|---|---|
| 看得到畫面、`P` 存出的 jpg 與 index 行一致 | 12 |
| Q1 有 `pip list` 證據 | 6 |
| Q2 指出 import 寫在函式裡、預覽模式不呼叫 | 6 |
| Q3 跑過並貼出真實錯誤訊息 | 3 |
| Q4 具體（有秒數或「沒有」），不是「還好」 | 3 |

## 作業二（第二節課）：辨識得到什麼、辨識不到什麼　40%

分成兩半，對應 lab1 與 lab2。

### A. 瓶子 vs 鉛筆（20%）

1. **一張你自己拍的照片**，裡面同時有**一個瓶子**和**一支鉛筆**
2. 跑 `python labs\lab1_detect.py --source data\mine`，交出標註後的圖
3. 回答：

   - **Q1** 瓶子的 `classes` 和分數是多少？鉛筆呢？
   - **Q2** 把 `--conf` 降到 `0.05` 再跑一次。鉛筆被認出來了嗎？
     **為什麼調門檻解決不了這個問題？**
   - **Q3** 用 `data\samples\test.mp4`（合成的幾何圖形）跑一次 lab2，看
     `index.jsonl` 裡的 `classes`。模型把圓形和三角形當成什麼？分數多少？
     **「模型給了一個有把握的錯答案」比「模型什麼都沒找到」危險在哪？**
   - **Q4** 你要讓它認得鉛筆，需要做什麼？（不用真的做，寫出步驟就好。）

### B. `--every` 的取捨（20%）

1. 用同一個來源跑三次，`--every` 分別是 **1 / 5 / 20**，其他參數一樣、都加
   `--loop --headless --max-frames 60`
2. 一張表：

   | `--every` | 讀幾幀 | 推論幾幀 | 整體 fps | 平均推論 ms |
   |---|---|---|---|---|
   | 1 | | | | |
   | 5 | | | | |
   | 20 | | | | |

3. 回答：

   - **Q5** 為什麼「跳過 48 幀」不是 bug？如果改成把每一幀都排進佇列處理，
     會發生什麼事？
   - **Q6** 你要用這支程式做「廠區設備巡檢」（慢慢飛、看得仔細最重要），
     `--every` 會選多少？為什麼？如果改成「偵測有人闖入」（要立刻發現）呢？
   - **Q7** 把 `--cooldown` 設成 0 跑一次，`runs\` 裡多了幾張？冷卻在保護什麼？

### 評分

| 項目 | 分數 |
|---|---|
| A：照片裡瓶子有框、鉛筆沒框，圖與 index 都交了 | 8 |
| A：Q1 有具體類別與分數 | 3 |
| A：Q2 指出「門檻調不出一個不存在的類別」 | 5 |
| A：Q3 答出誤判的類別並說明「有把握的錯答案」的風險 | 4 |
| B：三次都跑完，表格數字完整 | 8 |
| B：Q5 說出「延遲累積」 | 4 |
| B：Q6 兩種情境給出不同答案並說明理由 | 4 |
| B：Q7 有具體張數，並指出硬碟與重複畫面的問題 | 4 |

## 作業三（選讀，二選一）　30%

### 選項 A：首飛紀錄

> 需要真機與空曠場地。飛行部分沒有真機驗證過，請照
> [03-lab3.md](03-lab3.md) 的首飛檢查表逐項做。

1. **起飛前檢查表**（逐項打勾，附照片或影片更好）
2. **按鍵順序與發生什麼**，逐條寫。例如：
   ```
   1. --preview-only --speed 20 啟動，3 秒後看到畫面，電量 82%
   2. 按 T，起飛，懸停在約 80 cm
   3. 按 W 上升，機體持續上升 → 按空白鍵才停下來（這裡差點撞到天花板）
   4. 按 P，runs\ 多一張 snap000431.jpg
   5. 按 L，降落
   ```
3. **一件「程式阻止了你做的事」**，並說明為什麼那個阻止是對的。
   （最可能的是：畫面還沒出來時按 `T` 被拒絕。）
4. **一件你覺得應該改的設計**，以及你會怎麼改。

### 選項 B：整合工具

以 `lab4_patrol.py` 為基礎（見 [04-lab4.md](04-lab4.md)），交出：

1. **至少實作 [04-lab4.md](04-lab4.md)「動手改」裡的兩項**，其中一項必須是
   `--summary-json` 或 `report.py`（也就是要有一個**讀回 `index.jsonl`** 的東西）
2. **一份 README**，要能讓沒上過這門課的同學照著跑起來：安裝步驟、至少三道可以
   直接複製貼上的指令、以及一節**「已知限制」**
3. **一份量測報告**，至少三組數字，每組都要有指令、環境（CPU / 有沒有 GPU）、
   和一句解讀

> 「已知限制」這一節是評分重點。**寫得出自己的邊界，比假裝沒有邊界專業得多。**
> 參考 [90-設計決策.md](90-設計決策.md) 的「誠實的限制」。

### 評分（兩個選項同一套標準）

| 項目 | 分數 |
|---|---|
| 主體完成（檢查表逐項 / 兩項改動可跑） | 12 |
| 紀錄或文件具體、可重現 | 8 |

## 加分題（各 +5%，上限 +10%）

1. **換一顆真的認得你要的東西的權重。** 找一個公開資料集訓練（鉛筆、口罩都可以），
   用 `--weights` 換進去，附前後對照圖。**程式不准改任何一行** —— 如果非改不可，
   說明為什麼介面設計得不夠好。
2. **把「按一下持續移動」改成更安全的行為。** 例如加一個「N 秒沒收到按鍵就自動歸零」
   的 dead-man switch。附你怎麼測試它的說明。
3. **寫一支回歸測試腳本**，跑完能自動檢查：`index.jsonl` 行數 == jpg 數、
   `--dry-run` 不寫檔、`draw()` 不修改輸入影像。（提示：`--headless --max-frames`
   讓程式可以無人值守跑完，就是為了這個。）

## 誠實條款

- 用 AI 協助寫程式或報告**可以**，但要在報告最後寫一節「我用了什麼工具、
  它幫我做了什麼、我自己驗證了什麼」。
- **沒跑過的數字不要寫。** 編數字比交白卷嚴重得多。
- 沒做完就寫沒做完。這門課的核心價值之一就是「對自己的邊界誠實」——
  [90-設計決策.md](90-設計決策.md) 有一整節在示範怎麼寫。
