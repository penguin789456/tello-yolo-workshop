# 排錯手冊

照「訊息長什麼樣」找。看不到你的錯誤就往下翻到最後一節。

---

## 安裝與環境

### `ModuleNotFoundError: No module named 'ultralytics'`（或 `cv2`、`djitellopy`）

虛擬環境沒啟動。每開一個新的終端機都要做一次：

```bat
cd tello-yolo-workshop
.venv\Scripts\activate
```

提示字元前面要出現 `(.venv)`。

### `UnicodeDecodeError: 'cp950' codec can't decode byte ...`（裝套件時）

```
ERROR: Exception:
UnicodeDecodeError: 'cp950' codec can't decode byte 0xb8 in position 6
```

**pip 24.0 以前的版本是用系統編碼（繁中 Windows 是 cp950）去讀 requirements 檔的**，
檔案裡有 UTF-8 中文註解就會整個裝不起來。

教材的 `requirements.txt` 因此**刻意只用 ASCII 註解**，
每個版本釘法的中文理由都搬到這份文件裡。所以你照著 README 裝不會遇到這個。

**你自己加中文註解進 requirements 檔就會遇到。** 兩個解法：

```bat
python -m pip install --upgrade pip      :: 新版 pip 會當成 UTF-8 讀
```

或者就別在那個檔案裡寫中文 —— `requirements.txt` 是給機器讀的，說明寫在文件裡。

**可以帶走的原則：** 機器要讀的檔案（設定檔、資料檔、requirements）盡量維持 ASCII；
人要讀的說明放到文件。編碼問題永遠在最不方便的時候爆。

### `ERROR: ResolutionImpossible` / `conflicting dependencies`

`requirements.txt` 裡的版本互相打架。**這個教材遇過一次真的**：

```
The user requested numpy==2.2.5
ultralytics 8.3.0 depends on numpy<2.0.0 and >=1.23.0
```

解法是不要釘 numpy —— 讓 ultralytics 決定。`requirements.txt` 裡有註解說明。

心得：**釘你真的驗證過、會出事的東西；不要釘你只是想寫個數字的東西。**

### `OSError: [WinError 1114] 動態連結程式庫 (DLL) 初始化例行程序失敗`

```
Error loading "...\torch\lib\c10.dll" or one of its dependencies.
```

PyTorch 版本和這台機器的 VC++ 執行期不合。**這個教材也遇過真的** —— torch 2.14.0
裝起來了但 import 就炸。`requirements.txt` 因此明確釘了 `torch==2.7.0`。

如果你自己升級 torch 之後出現這個，就降回去：

```bat
pip install torch==2.7.0 torchvision==0.22.0
```

### 一直卡在 `Downloading yolo26n.pt`

權重沒放進 `models\`，程式在連網下載。照 README 步驟 2 抓一次放好，之後就不會再下載。

## 執行期

### 每張圖都 `0 處`，一個框都沒有

**這是正常的，不是壞了。** `yolo26n.pt` 是 COCO 預訓練權重，它認得人、車、椅子那
80 類。內附的 `data\samples\` 是**合成的幾何圖形**，COCO 裡沒有「圓形」「方塊」
這些類別。

教材用它示範整條管線。想看到有意義的框，拿一張有人或有車的照片試：

```bat
python labs\lab3_detect.py --source video --path 有人的照片.jpg --conf 0.3 --headless --snap-every 1
```

要辨識你真正要的東西，換一顆用那個資料集訓練出來的權重（`--weights models\best.pt`）。
見 [90-設計決策.md](90-設計決策.md) 的「誠實的限制」。

### 把 `--conf` 調低之後，冒出 `orange` / `bicycle` / `tv`

同一個原因，只是更明顯：COCO 裡沒有「圓形」「三角形」，模型只能在 80 個既有類別裡
挑一個最像的 —— 於是圓形變成橘子、方塊變成電視。

但看一下分數：**最高只有 0.17**。它自己也沒把握，是你把門檻降到 0.05 逼它講話的；
預設 `--conf 0.25` 下這些根本不會出現。

**分類模型永遠會給你一個答案。** 它不會說「我不知道」—— 門檻放多低，它就講多少話。
驗證輸出對不對是你的責任，不是模型的。

### `找不到來源：...` / `找不到影片檔：...`

路徑打錯。Windows 上用反斜線 `\`，路徑有空白要整個用雙引號包起來：

```bat
python labs\lab3_detect.py --source video --path "D:\我的 照片\a.jpg" --headless --snap-every 1
```

### `無法開啟來源：0`

沒有攝影機，或攝影機被別的程式（視訊會議軟體、相機 App）占用。關掉那些再試。

### 影片播得像快轉

你加了 `--headless`。開窗的時候程式會照影片 fps 節流（`cv2.waitKey(delay_ms)`），
`--headless` 就是要盡快跑完。

### `--max-frames 60` 但只讀到 40 幀就結束

`data\samples\test.mp4` **只有 40 幀**（15 fps、約 2.7 秒），播完就結束了。
三支範例都沒有 `--loop`（無人機的畫面不會「播完」，所以沒做這個參數）。

要跑久一點就把 `--max-frames` 設在 40 以內，或者用自己的影片：

```bat
python labs\lab3_detect.py --source video --path data\samples\test.mp4 --headless --max-frames 40 --snap-every 10
```

### 按 `q` / `p` 完全沒反應

焦點不在影像視窗上。**用滑鼠點一下那個視窗**，鍵盤事件才會進 `cv2.waitKey`。

### CPU 燒滿、風扇狂轉

三支範例都不做連續推論，所以正常不會這樣。如果發生了，檢查你是不是把 `detect()`
搬進主迴圈了 —— 辨識應該只在按 `P` 的時候做。

### 按 `P` 之後要等好幾秒才有反應

模型沒在啟動時載好。正常情況下啟動就會印「模型載入 + warmup：3015 ms」，之後按
`P` 只要 50~60 ms。如果你改過程式、把 `YOLO(weights)` 搬進 `snap()` 裡，就會變成
每次按都重載一次。見 [90-設計決策.md](90-設計決策.md) 第 1 條。

### 印出來的中文是亂碼

三支範例開頭都會把 stdout/stderr 轉成 UTF-8，所以直接跑通常沒問題。還是亂碼的話，
在終端機先跑：

```bat
chcp 65001
```

## Tello

### `連不上 Tello：Command 'command' was unsuccessful for 4 tries`

**要等約 28 秒才會放棄**（djitellopy 重試 4 次 × 7 秒），不是卡住了。

檢查順序：

1. 電腦的 Wi-Fi 連到 `TELLO-XXXXXX` 熱點了嗎？（沒有密碼。Windows 會顯示
   「無網際網路」，這是正常的）
2. 無人機電源開了嗎？機頭燈在閃嗎？
3. 上一個 python 程式還開著嗎？它會占住 UDP 8889

### `OSError: [WinError 10048]`

UDP 埠被占用，通常是另一個 python 還活著。找出來關掉：

```bat
netstat -ano -p UDP | findstr 8889
taskkill /PID <上面查到的 PID> /F
```

或直接關掉所有 python：`taskkill /IM python.exe /F`（會關掉**全部**，小心）。

### `10 秒內沒有畫面`

上一次沒關乾淨，UDP 11111 還被舊的解碼器占著。關掉所有 python，等五秒，重跑。

程式等 10 秒就放棄是刻意的 —— **無限等待的程式看起來就像壞了**。

### 畫面顏色很怪，天空是橘色的

RGB / BGR 沒轉。djitellopy 給的是 **RGB**，cv2 全家吃 **BGR**。
`read_frame()` 裡那行 `cv2.cvtColor(frame, cv2.COLOR_RGB2BGR)` 就是在處理它。

**如果你自己改程式時弄掉了這行：** 不只顏色會反，送進 YOLO 的張量也跟訓練時不一致，
分數會怪。這是「看起來能跑但結果錯」的經典例子。

### 按 `T` 沒有起飛，只印了「尚未看到畫面，取消起飛」

**這是設計，不是 bug。** 規則 1：沒有畫面等於盲飛。等畫面出來再按。
見 [01-lab1.md](01-lab1.md)。

### `起飛失敗：...`

訊息後面會印電量與溫度。最常見的兩個原因：

- **電量低於 50%** → 換電池
- **機身過熱** → 放著涼幾分鐘

### 飛機一直往前飛，放開按鍵也不停

**按空白鍵。** 這是介面的限制不是 bug：`cv2.waitKey` 只有「按下」事件、沒有
「放開」事件，所以速度會 latch 住。要停就按空白鍵或反向鍵。

飛之前請先讀 [01-lab1.md](01-lab1.md) 的鍵盤那節。

### 方向鍵沒反應（但 `W` / `A` / `S` / `D` 有用）

`cv2.waitKeyEx` 的方向鍵回傳值**不跨平台**。程式裡寫的是 Windows 的值。
在 Linux / macOS 上請用備援鍵：**`8` `2` `4` `6`**（前後左右）。

### 程式結束了但飛機還在空中

你加了 `--no-land-on-exit`。預設是會自動降落的。**加了那個參數就是你要自己接手。**

## 還是找不到答案

三個步驟：

1. **只看錯誤訊息的最後三行。** Python 的 traceback 是由外往內，最後一行才是真正的
   錯誤。
2. **把那一行貼去搜尋**，但先把你電腦上的路徑刪掉（那是雜訊）。
3. **縮小範圍。** 用 `--no-model` 排除模型問題、用 `--source video` 排除無人機問題：

```bat
python labs\lab3_detect.py --source video --path data\samples\test.mp4 --headless --max-frames 5 --no-model
```

這道指令不載模型、不寫檔、不碰無人機。如果它過了，問題不在流程本身。
